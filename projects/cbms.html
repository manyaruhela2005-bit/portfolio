Project Overview

CBMS (Central Bank Management System) is a centralized banking management web application designed to bring multiple banking operations into one unified platform. It leverages a full-stack architecture to seamlessly integrate accounts, transactions, and internal banking workflows.

The Problem

Traditional banking systems often operate independently, which creates:

  • Multiple logins for different banks
  • No unified financial overview
  • Fragmented banking data & data redundancy
  • Inefficient inter-bank transactions
  • No centralized transaction tracking
  • Complex KYC and loan processing
  • Limited interoperability

The Solution

CBMS resolves these fragmentation issues by providing:

  • Single login for multiple banking operations
  • Centralized account & transaction management
  • Role-based access controls
  • Unified KYC verification & Loan processing
  • Beneficiary, Complaint, and Feedback management
  • Administrative controls and audit logging

Key Features & Modules

Core System Modules

  • Authentication Module: Secure login and registration.
  • Dashboard Module: Role-specific system overviews.
  • Account Management: Cross-bank account handling.
  • Transaction Module: Secure inter-account fund transfers.
  • Database Module: PDO-driven relational processing.

Operational Modules

  • KYC Module: Document submission and verification workflows.
  • Loan Module: Application, review, and tracking system.
  • Beneficiary Module: Simplified payee management.
  • Support Modules: Complaints and Feedback systems.
  • Audit & Admin: Extensive system logging and employee management.

User Roles

The application implements strict role-based access control to ensure secure, segmented functionality for different users.

1. User / Customer

  • Register, log in, and manage profile
  • View personal dashboard and account balance
  • Manage multiple bank accounts & beneficiaries
  • Transfer money (requires password re-confirmation)
  • Apply for and track loans
  • Complete KYC requirements
  • Submit complaints and track feedback

2. Employee

  • Access an employee dashboard
  • View system-wide statistics
  • Process KYC requests
  • Review, approve, or reject loan requests
  • View and manage complaints
  • View transaction history & review feedback
  • Access audit logs

3. Admin

  • Create, edit, delete, and block users
  • Manage employees and other administrators
  • Manage banks and oversee accounts
  • Manage loans and resolve escalated complaints
  • Review feedback and access complete audit logs

Database Design

The system uses MySQL as a centralized relational database. Important concepts demonstrated include Primary/Foreign keys, normalization, referential integrity, and data validation.

Important Entities:

  • Users: Central identity entity governing role-based access.
  • Accounts: Connects users with banks, storing balances, types, and status.
  • Transactions: Immutable records of deposits, withdrawals, and transfers.
  • Operations: Loans, KYC, Beneficiaries, Complaints, Feedback.
  • System: Employees, Audit Logs, Banks.
